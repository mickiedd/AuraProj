## "Discard all local changes, then build" — the change list was a false positive

### 1. There were no real local changes: the 117-file "modified" list is a Git LFS artifact

`git status` reported **117 modified** `*.uasset` / `*.umap`. Verified every single one:

```
git hash-object --no-filters <file>   ==   git ls-files -s <file> blob hash
```

→ **117 identical, 0 truly different.** The working tree is byte-identical to HEAD.

**Root cause:** the **committed blobs are raw binaries** (`BP_AuraAIController.uasset` = 19536 B in
the index and in `HEAD:`), while `.gitattributes` declares `*.uasset filter=lfs`. So the LFS clean
filter rewrites the working file to a ~130 B pointer, which can never equal the committed binary →
a permanent "modified". `git lfs status` shows both sides equal (`Git: 1571fb5 -> File: 1571fb5`),
and `git diff --stat` shows the tell-tale `Bin 19536 -> 130 bytes`.

**Consequence: `git restore .` does NOT clean the list.** It rewrites the same binary from HEAD and
the pointer mismatch reappears on the next status. Discarding is a no-op here — nothing was at
risk, but nothing would have been gained either.

### 1b. Fix applied: renormalized to LFS pointers (commit `b2d258b`)

`git add --renormalize --pathspec-from-file=<117 paths>` → exactly 117 staged, all
`Bin <big> -> ~130 bytes`, then committed. `git status` is now clean of assets (0 remaining, was
117). Verified first that all 117 referenced LFS objects exist in `.git/lfs/objects` (117 found,
0 missing) — do this **before** committing, or the commit references objects that may not exist.

Scoped the renormalize to the 117 paths rather than `git add --renormalize .` so it could not drag
in unrelated text/line-ending changes. Also confirmed the only hooks are the stock
`git lfs post-commit` / `post-checkout` / `post-merge` / `pre-push` shims — nothing custom that
rewrites files.

**Not pushed.** The commit is local; `main` is 1 ahead of `origin/main`. Pushing uploads the 117
LFS objects to GitHub, so it was left for explicit approval. Rollback: `git reset --hard e1f67f8`.

Also confirmed: no untracked files, no existing stashes, 4673 LFS objects present locally.
