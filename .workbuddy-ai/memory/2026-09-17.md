## Wuxianmen V5 Core reference tuning, revision 2 (`reftune2`)

Applied the `unreal-asset-reference-tuning` workflow to
`BP_Wuxianmen_V5_4K_Core` against `Docs/Reference/GateSheets/Wuxianmen-reference.png`.
The user chose "fix roof + ridge" and "include the material pass" from the
options presented.

**Root cause found (all measured from the source assembly, not the renders):**
the imported roof was inverted. Every tile strip and both wood roof decks rise
from `z 12.75 m` at `y = 0` to `z 15.72 m` at `|y| = 4.5 m` — a valley. Both
ridge bars were also 90° wrong: `main_ridge` measured `0.42 × 22.5 × 0.42 m`
along Y while the roof pitches along Y and is only 8.7 m deep there, so 6.9 m
protruded past each eave. Their lengths (22.5 / 21.0 m) match the roof widths in
X (22.59 / 21.08 m) and their seat heights match the un-inverted apexes, which is
what identified the intended design. `HISM_004_ridge_000010` was additionally
bound to a roof-tile mesh while `main_ridge.uasset` sat unused.

**Repair:** 180° rotation about the world X axis through each tier mid-plane
(`main` pivot z 1423.5 cm, `lower` 1251.5 cm) — a rotation rather than a Z mirror
so winding and normals survive. 328 of 5,103 instance transforms changed.
Ridge rebound to `main_ridge`, re-axed onto X, seated at z 1572 / 1338 cm.

**Second-order trap:** a Z mirror reverses vertical stacking, so the mirroring
lifted the wood roof decks above the tiles and hid them (the roof rendered as
bare wood). The decks are mirrored about a pivot 20 / 15 cm lower, seating them
9–42 cm below the tile tops.

**Materials:** roof tile `U = 1/14.629` (one column across the 0.359 m strip) and
`V = frac(UV·2.8)·0.4431` (14 courses, 0.362 m pitch); stone tiling was
*inverted* (6.36 instead of `1/6.36`) which had shrunk each stone to 13 mm inside
a 0.56 m block — now one stone per block plus per-instance custom data
(`num_custom_data_floats = 1`, 4,213 values) for UV offset and ±15% tone; plaster
tint darkened; the plaque had **no texture at all** (flat gold tint) so a
generated 五仙門 board texture was imported and bound.

New private materials all use the `_RefTune2` suffix; the prior
`_ReferenceTuned` / `_ReferenceTuned_RoofTilingFix` materials remain the rollback
path. Baseline snapshot doubles as the geometry rollback path.

**Artifacts:** archive record + diagram in
`Docs/Reports/Change-Archive/2026-09-17-wuxianmen-reference-tuning-revision-2.{md,svg}`,

## Wuxianmen V5 FullPBR reference tuning, revision 2 (`reftune2`)

Applied the same workflow to `BP_Wuxianmen_V5_FullPBR` (the user chose "borrow
Core's authored tile sheet" when told the FullPBR source textures carry no
architectural pattern).

**Key finding:** the FullPBR assembly is *geometrically identical* to Core —
same 7 components, same 5,103 instances, and every component's recorded transform
payload matches the Core baseline exactly (and the source GLBs have identical
geometry and node transforms). So the same correction pivots applied unchanged.
328 transforms changed, 4,775 preserved.

**FullPBR-specific:** the source archive's sheets are pattern-free (p99 image
gradient on stone `0.004` vs Core's `0.071` — 18×; roof `0.012` vs `0.051` — 4×;
`_Repaired` PNGs byte-identical to the archive's own). So the Core package's
authored 4K tile sheet was **copied** into
`Saved/RawModelImport/V5/RefTune2/Wuxianmen_V5_FullPBR/` and imported as
`Textures/RoofTile_{BaseColor,Normal,Roughness}_4K_TileSheet` for the new roof
material. Stone gained per-instance custom data (UV offset + ±20% tone) at tiling
0.06. FullPBR packs roughness/metallic as G/B in MetallicRoughness maps (Core used
a separate roughness map) — the new materials sample the right channels.

**Blocker encountered — the capture harness:** partway through this session
`take_high_res_screenshot` stopped tracking the camera and wrote the same stale
frame for **every** view, for both variants. Ruled out: camera readback,
missing actors, `editor_invalidate_viewports()`, a 10 s delay,
`force_game_view=False`, an explicit `CameraActor`, and a `SceneCapture2D` +
`export_render_target` path (which silently wrote no file). Most likely the
editor window is in the background and Unreal throttles viewport rendering;
`EditorPerformanceSettings` is not exposed to Python so it cannot be toggled.
**Ask the user to foreground the editor and re-run the capture set.** Numeric
validation does not need rendering and passed regardless.

**Open items:** the FullPBR plaque art reads 五仙門 left-to-right in texture space
while the reference board reads 門仙五; the UV orientation was left unchanged
rather than guessed (a front-on capture is needed). The stone tiling change is
reasoned but not visually verified.
