# Crunch migration completion plan

## Intent

Replace the ambiguous “combo implemented” stopping point with an implementation-grade path to a complete Crunch Character/Pawn migration. The plan covers current review debt, authored network timing, final Crunch presentation assets, all five character skills, role/HUD lifecycle integration, matching packaged normal-flow evidence, and independent sign-off.

## Planned behavior change

- Before: Crunch is selectable but uses Aura's mesh/ABP, owns only the LMB combo, retains four unresolved review findings, and lacks matching-build in-world proof.
- After the plan is executed: Crunch owns its final avatar/presentation, LMB Combo, UpperCut, Dash, GroundBlast, and Tornado through AuraProj's server-authoritative role/GAS contracts.
- Completion cannot be claimed from automation or Login/Loading alone. A matching packaged listen host and remote client must enter gameplay and visibly exercise every skill.
- Dedicated-server and production-release status remain separately classified and may be `BLOCKED` without becoming a false PASS.

## Plan validation

- Grounded the plan in the current AuraProj diff, migration archives, pending review findings, source Crunch C++ ability behavior, source asset paths, current RoleConfig, and AuraProj role/grant/test architecture.
- Every one of the ten days names concrete files/assets, authority/data rules, ordered implementation steps, tests/commands, fixtures, failure/timeout semantics, artifacts, a completion gate, and anti-goals.
- The plan freezes the five-input mapping and requires Day 01 to export/hash source Blueprint/CDO tuning rather than inventing replacement values.
- Markdown links, SVG XML, and `git diff --check` are part of this planning job's validation.
